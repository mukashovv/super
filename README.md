# Супер Таблица

Статическое приложение для учёта личных финансов в сомах. Файлы приложения и CNAME размещаются в корне нового репозитория GitHub Pages. Адрес сайта — https://supertable.mukashov.com/.

## Посмотреть на компьютере

Откройте `index.html`, нажмите **Попробовать бесплатно → Открыть локальную таблицу**. Этот режим доступен при пустых настройках Supabase. Записи принадлежат этому браузеру. Для проверки через локальный HTTP-сервер запустите из каталога проекта:

```sh
python3 -m http.server 8000
```

Откройте страницу `http://localhost:8000/super_tablica/`. Если сервер запущен внутри папки приложения, используйте `http://localhost:8000/`.

## Установка на устройство

После публикации на GitHub Pages откройте сайт и нажмите **Установить** в верхнем меню. Кнопка открывает системное окно установки или показывает шаги для текущего браузера. В установленном приложении кнопка скрыта. Для синхронизации с аккаунтом нужен интернет.

## Подключить Supabase

1. Создайте проект Supabase. Откройте **SQL Editor**, скопируйте туда содержимое `setup.sql` и выполните его. Скрипт создаёт таблицы в отдельной схеме и серверные функции для приложения.
2. В `config.js` укажите **Project URL** в поле `supabaseUrl` и **Publishable key** (или прежний публичный `anon` key) в поле `supabasePublishableKey`. Ключи типа `secret` и `service_role` предназначены только для сервера.
3. В **Authentication → Sign In / Providers** включите Email/Password. В **URL Configuration** укажите полный адрес приложения в **Site URL** и **Redirect URLs**, включая завершающий слэш. Для текущей структуры это `https://supertable.mukashov.com/`. Добавьте адрес локального HTTP-сервера, если хотите проверить регистрацию до публикации.
4. При включённом подтверждении адреса пользователь следует по ссылке из письма. Для отправки писем клиентам настройте SMTP в Supabase.
5. Поместите файлы в ветку, из которой публикуется GitHub Pages. Для нового репозитория выберите **Settings → Pages → Deploy from a branch** и папку публикации. Сборка приложения не требуется.

Настроенная версия загружает клиент Supabase из jsDelivr. Каждый аккаунт начинает с пустой таблицы. Облачная версия хранит операции и долги в Supabase. Локальные пробные записи в аккаунт автоматически не переносятся.

## Полный доступ и оплата

При первом открытии аккаунту назначается один бесплатный календарный месяц. Эта вкладка остаётся доступной для редактирования. Новые месяцы и раздел «Долги и платежи» доступны после активации полного доступа. Supabase проверяет подписку при чтении, изменении и удалении долгов и регулярных платежей. После окончания срока история сохраняется и снова открывается при продлении. Для существующего проекта выполните обновлённый `setup.sql` в SQL Editor. Для покупателя с полным доступом текущий месяц создаётся автоматически. Также можно вручную создать вкладку за прошлый или будущий месяц.

Кнопка **Запросить оплату** открывает WhatsApp поддержки проекта. В `config.js` можно указать собственный `supportUrl` и прямой HTTPS-адрес оплаты в `paymentUrl`. При заполненном `paymentUrl` кнопка ведёт на оплату. В карточке полного доступа доступны запросы на продление через WhatsApp: 1 год за $20, 3 года за $48 или 5 лет за $65.

### Управление участниками

Для обновления действующего проекта выполните весь актуальный `setup.sql` в SQL Editor. Однократная настройка привязывает управление к подтверждённому аккаунту growfinansy@gmail.com по его идентификатору Supabase. Если почту подтвердили позже, выполните скрипт ещё раз. После обновления сайта войдите под этим аккаунтом и откройте нижнюю вкладку **Участники**.

Найдите пользователя по почте, нажмите **Выдать доступ**, выберите **1 год**, **3 года** или **5 лет** и подтвердите. Действующая подписка продлевается от даты окончания. Для нового срока отсчёт начинается с сегодняшней даты по времени Бишкека. Доступ заканчивается в начале указанной даты. Ранее выданный бессрочный доступ сохраняется. Пользователь увидит статус после обновления страницы или нажатия **Проверить доступ**.

## Как воспроизводятся расчёты

- Доход за вычетом расхода даёт итог дня, месяца и года. Суммы хранятся в тыйынах. Несколько поступлений за день можно записать отдельными строками.
- Распределение целей считается от итога. Начальная доля «Подушки» равна 20%. Доли и названия можно изменить для каждого месяца. Новая вкладка наследует настройки ближайшего предыдущего месяца.
- Годовая сводка показывает 12 месяцев и сравнивает прибыль выбранного месяца с предыдущим, в том числе при переходе с января на декабрь. Прочерк означает отсутствие вкладки. Ноль означает, что вкладка создана и её итог равен нулю.
- В долгах остаток равен основной сумме плюс переплата минус внесённые платежи. Запланированные платежи сохраняются с датами и влияют на остаток после отметки о внесении. Закрытый долг сохраняет историю. При положительном остатке перенос в «Выполнено» требует подтверждения окончательного платежа. На телефоне для переноса есть кнопка.
- На карточке долга нажмите **Редактировать**, укажите дату первого платежа, сумму в месяц и срок в месяцах. В месячной таблице название долга появится за четыре календарных дня до каждой даты платежа. Если в месяце нет нужного числа, платёж приходится на последний день месяца.
- Чтобы отметить оплату, нажмите **Внесено** на карточке или откройте напоминание в календаре. На карточке можно выбрать расчётный месяц и ввести фактическую сумму. В окне дня нажатие на строку отмечает оставшуюся сумму платежа. Полностью оплаченный платёж становится зелёным в окне и в таблице. Повторное нажатие снимает последнюю отметку. Отдельные операции можно проверить в карточке или в разделе **Долги → История платежей**. Операции вне графика по долгу с графиком показываются в истории.
- В разделе **Долги → Регулярный платёж** можно добавить соцфонд, аренду и другие ежемесячные платежи. Укажите название, сумму и дату первого платежа. Напоминания повторяются каждый месяц до удаления карточки. Отметка оплаты привязана к выбранному месяцу.
- Значок корзины в правом верхнем углу карточки позволяет удалить долг или регулярный платёж вместе с историей и напоминаниями. Для включения удаления в существующем проекте Supabase выполните обновлённый `setup.sql` в SQL Editor.
- Изменения записываются с номером версии. Если вкладка или долг уже изменены на другом устройстве, приложение обновляет данные и предлагает повторить изменение.
