# Супер Таблица

Статическое приложение для учёта личных финансов в сомах. Основная страница проекта открывается по пути `/super_tablica/`. В отдельном репозитории эту же папку можно разместить в корне GitHub Pages.

## Посмотреть на компьютере

Откройте `index.html`, нажмите **Попробовать бесплатно → Открыть локальную таблицу**. Этот режим доступен при пустых настройках Supabase. Записи принадлежат этому браузеру. Для проверки через локальный HTTP-сервер запустите из каталога проекта:

```sh
python3 -m http.server 8000
```

Откройте страницу `http://localhost:8000/super_tablica/`. Если сервер запущен внутри папки приложения, используйте `http://localhost:8000/`.

## Подключить Supabase

1. Создайте проект Supabase. Откройте **SQL Editor**, скопируйте туда содержимое `setup.sql` и выполните его. Скрипт создаёт таблицы в отдельной схеме и серверные функции для приложения.
2. В `config.js` укажите **Project URL** в поле `supabaseUrl` и **Publishable key** (или прежний публичный `anon` key) в поле `supabasePublishableKey`. Ключи типа `secret` и `service_role` предназначены только для сервера.
3. В **Authentication → Sign In / Providers** включите Email/Password. В **URL Configuration** укажите полный адрес приложения в **Site URL** и **Redirect URLs**, включая завершающий слэш. Для текущей структуры это `https://mukashov.com/super_tablica/`. Добавьте адрес локального HTTP-сервера, если хотите проверить регистрацию до публикации.
4. При включённом подтверждении адреса пользователь следует по ссылке из письма. Для отправки писем клиентам настройте SMTP в Supabase.
5. Поместите файлы в ветку, из которой публикуется GitHub Pages. Для нового репозитория выберите **Settings → Pages → Deploy from a branch** и папку публикации. Сборка приложения не требуется.

Настроенная версия загружает клиент Supabase из jsDelivr. Каждый аккаунт начинает с пустой таблицы. Облачная версия хранит операции и долги в Supabase. Локальные пробные записи в аккаунт автоматически не переносятся.

## Полный доступ и оплата

При первом открытии аккаунту назначается один бесплатный календарный месяц. Эта вкладка остаётся доступной для редактирования. Новые месяцы разрешает сервер после активации полного доступа. Для покупателя с полным доступом текущий месяц создаётся автоматически. Также можно вручную создать вкладку за прошлый или будущий месяц.

Кнопка **Запросить оплату** открывает WhatsApp поддержки проекта. В `config.js` можно указать собственный `supportUrl` и прямой HTTPS-адрес оплаты в `paymentUrl`. При заполненном `paymentUrl` кнопка ведёт на оплату. Стоимость и способ расчёта назначает владелец.

### Управление участниками

Для обновления действующего проекта выполните весь актуальный `setup.sql` в SQL Editor. Однократная настройка привязывает управление к подтверждённому аккаунту growfinansy@gmail.com по его идентификатору Supabase. Если почту подтвердили позже, выполните скрипт ещё раз. После обновления сайта войдите под этим аккаунтом и откройте нижнюю вкладку **Участники**.

Найдите пользователя по почте, нажмите **Выдать доступ**, выберите **1 год** или **3 года** и подтвердите. Срок отсчитывается от сегодняшней даты по времени Бишкека и заменяет предыдущий срок. Доступ заканчивается в начале указанной даты. Ранее выданный бессрочный доступ сохраняется. Пользователь увидит статус после обновления страницы или нажатия **Проверить доступ**.

## Как воспроизводятся расчёты

- Доход за вычетом расхода даёт итог дня, месяца и года. Суммы хранятся в тыйынах. Несколько поступлений за день можно записать отдельными строками.
- Распределение целей считается от итога. Начальная доля «Подушки» равна 20%. Доли и названия можно изменить для каждого месяца. Новая вкладка наследует настройки ближайшего предыдущего месяца.
- Годовая сводка показывает 12 месяцев и сравнивает прибыль выбранного месяца с предыдущим, в том числе при переходе с января на декабрь. Прочерк означает отсутствие вкладки. Ноль означает, что вкладка создана и её итог равен нулю.
- В долгах остаток равен основной сумме плюс переплата минус внесённые платежи. Запланированные платежи сохраняются с датами и влияют на остаток после отметки о внесении. Закрытый долг сохраняет историю. При положительном остатке перенос в «Выполнено» требует подтверждения окончательного платежа. На телефоне для переноса есть кнопка.
- Изменения записываются с номером версии. Если вкладка или долг уже изменены на другом устройстве, приложение обновляет данные и предлагает повторить изменение.
